# Launcher 1.3 release qualification

**Release status: blocked.** Qualification started at `e648e7b44f770b275bcdc7b5f7d1aae730d1745d`. The exact active renderer loaded in Darkshire but the disposable client crashed during the noon check. No executable fingerprint is approved for the graphics feed. The public feeds and the v1.2.0 game manifest were untouched.

## Full-client qualification

- The actual launcher verified the full disposable copy of `C:\WoWClient` against the v1.2.0 manifest. It quarantined the obsolete `patch-v.mpq` and Play reached the login screen with the optional graphics absent.
- Through the actual download and install handlers over loopback HTTP, the clone received the eight-file loader QA ZIP. SHA-256 `966368568e12b951063851401faedaa590696b32deb4fa81841a1ffa642929db`. All eight installed hashes matched. The archive carries the exact target DLL and zero-scatter INIs, with all effect files omitted. It is a private test input.
- Play reached Darkshire on the manifest-supported executable. Fresh logs confirmed CoAVolFog world hooks, upstream DXVK 3.1.1 x86 and the system ReShade 6.8.0.2157 x86 layer. No Lexara loader was present. ReShade reported the missing shader directory, so the full effect preset was unavailable.
- The global overlay showed `Sun scatter 0.00`. Selecting noon and pressing the renderer's local **Hold** control in Darkshire caused WoW Error #132, `0xC0000094 INT_DIVIDE_BY_ZERO` at `Wow.exe:0094BF6B`. Disassembly of the tested executable shows `idiv ecx`, and the crash report records `ECX=0`. The clock action preceded the fault. The evidence does not establish that Sun Scatter caused it. The dusk scene is not a daylight or region-boundary pass. See the local crash report and renderer logs in `obj/qualification-full/evidence`.
- The launcher removed all eight managed files and Play reopened WoW. The disposable executable retained SHA-256 `4c459de64d38b5795becc6c01a03ba00d34686598fae707c442446722617868a`. The separate local data files were retained as QA evidence.

## Compatibility and acceptance

- Working test fingerprint `3bd126a7d69a9177970cb0823f7e251f8b641f3625d599210ce6b2ae5ab6687c`. This differs from the required game manifest fingerprint.
- Required v1.2.0 fingerprint `4c459de64d38b5795becc6c01a03ba00d34686598fae707c442446722617868a` is present at `C:\WoWClient\Wow.exe`. Both binaries are i386 with image base `0x00400000` and timestamp `0x4C2452FE`. The seven GameObject adapter code ranges and two vtable slots match byte-for-byte. That static comparison covers the adapter gate and does not establish full renderer compatibility.
- The same private ZIP passed opt-in download, verification, installation and removal through the launcher over loopback HTTP for disposable executable copies of both fingerprints. Each test matched all 34 installed file hashes against the ZIP and verified that removal left the executable unchanged. These copies did not contain a playable game. The 24 launcher fixtures and the WinForms progress checks also passed.
- The standalone loopback bootstrap and updater passed signed replacement, restart, settings preservation, interrupted handoff and failed-startup rollback. The bootstrap 1.3.0 SHA-256 was `5f4d888f298951ca5d517fb9e9b244c53d6a5f47e24a8bed731372a8c74073aa`. The updater 1.3.1 SHA-256 was `56bbde0393d0819d9e0035f0f5f0136ecaddcec55ec08c25ca9608153136a77a`. Both builds were tied to the ephemeral QA feed.
- With graphics absent, the game patch path installed and verified all 27 local v1.2.0 archives against a synthetic base client. The repeat check made no payload requests.
- After resolving the clock crash and effect prerequisites, repeat the full-client test. Check a daylight scene where the distant trees previously washed out, then cross a region boundary and verify the effective Sun Scatter value remains zero. Record the visual result and load logs before approving a fingerprint.

## Signing and coordinated publish order

Follow [LAUNCHER-RELEASE-1.3.md](LAUNCHER-RELEASE-1.3.md). Build bootstrap 1.3.0 and updater 1.3.1 with both approved ECDSA P-256 public keys and `StagingFeeds` disabled. Have the approved signers produce the P1363 signatures over the exact UTF-8 metadata bytes and verify both signatures using the embedded public keys. The loopback smoke signs with ephemeral QA keys only. Production key provisioning, signed metadata and the key-equipped binaries were deferred.

After both channels pass release acceptance, stage the immutable launcher EXE on `launcher-v1.3.1` and the qualified graphics ZIP on its `lumenveil-v<version>` release. Verify the published asset hashes, then activate the signed `launcher-feed/metadata.json` and `lumenveil-feed/metadata.json` pointers and make the 1.3.0 bootstrap available as part of the same rollout. Keep the existing v1.2.0 patch manifest and game assets in place.
